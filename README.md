# 发版闸（Shipgate）

骨架：发版申请入闸 → 环境晋升裁决 → 放行/回滚窗 → 发布结果对账。

## 放行与探针关系：全站唯一策略

本站在两种互斥做法中贯彻 **方案二（Arm B）**：

> **允许先切流 · 缺口明示可核**（策略码 `SWITCH_FIRST_GAP_VISIBLE`）

即：放行写口允许在探针暂红、甚至暂时没有实例挂接时完成发版单 `已放行`
与名册产版本切流；但**任何定位面都不得把它静默算成成功或偷偷抹绿**。
放行回执、名册产版本、实例健康行、发版单、总览、对账缺口标、审计切流记录
全部经由同一个纯评估核心 `backend/app/services/outcomes.py:evaluate_slot`
得到统一结局与缺口标。

统一结局码（中文即规范值，整站不另造近义词）：

| 结局 | 含义 | 统一缺口标 |
| --- | --- | --- |
| `探针全绿` | 名册版本有同版本实例且全绿 | （空，不挂缺口） |
| `红灯计数中` | 有红灯，连续失败次数未达阈值 | `缺口·红灯计数` |
| `红灯超标` | 红灯连续失败次数达到/超过阈值 | `缺口·红灯超标` |
| `探针待报` | 实例已挂接（含对账补挂），尚无回报 | `缺口·待首探` |
| `无实例挂接` | 名册已切版本，但没有同版本实例可探 | `缺口·无实例挂接` |
| `未切流` | 名册版本为空 | — |

- **探针失败次数阈值**：默认 `3`，设置键 canonical 为 `探针失败阈值`。
  写任一近义键（`探针失败次数阈值`、`失败次数阈值`、`连续失败阈值`、
  `探针阈值` 等，或任何含“阈值 + 失败/探针/红灯”的键）都会自动写穿同步到
  canonical 键，避免“设置页改了阈值、判定仍读旧键”。取值夹在 1–99。
- 失败次数按实例**连续**累计：`探针红` 走原子
  `fail_count = fail_count + 1`（并发不丢计数）；`探针绿`/`探针待报` 清零。
- 放行写口对“同版本已存在的实例行”只回写发版单关联，**保留原灯色与失败次数**，
  不会把放行前已红透的实例静默刷绿。
- 总览设有醒目的 **“红灯已切流”** 露口：名册产版本已切到该版本、而该版本槽位
  当前为红（计数中/超标）时必挂；对账有同样的 `红灯已切流` 标记与缺口台账。
- **半截无实例挂接**：可用故障注入 `故障注入: "跳过挂接"` 复现。该态判为
  `无实例挂接` 并全站挂缺口；`POST /api/对账/重放`（别名 `/api/对账/修复`、
  `/api/结局/重放`）幂等地为“有放行/切流证据但无同版本实例”的槽位补挂一行
  `探针待报`（`backfilled=1`），使其可探而不是假绿。服务启动时也会自动收敛一次，
  因此不会长期“已放行但无探针对象”。
- 范围仅限**放行与探针一致性**。回滚后旧版本残留实例的清理另立，不在本次范围内
  （对账仍保留 `环境红灯总数` 这一环境口径计数，槽位口径只算名册当前版本）。

## 主要接口

- 策略/名册：`GET /api/名册`
- 实例册：`GET /api/实例`（别名 `/api/实例册`）、`POST /api/实例/登记`、
  `POST /api/实例/{id}/健康`
- 放行写口：`POST /api/发版单/{id}/晋升`（目标环境 `产` 即生产切流），
  响应顶层保留原发版单字段，并嵌套 `放行回执`
  （回执号、切流台账编号、名册产版本、实例编号、结局、缺口标、红灯已切流、
  阈值、失败次数、实例健康行等）
- 总览：`GET /api/总览`（含 `策略`、`阈值`、`红灯已切流`、`缺口台账`）
- 对账：`GET /api/对账`、`POST /api/对账/重放`
- 审计：`GET /api/审计?类别=切流&关键词=...&关联编号=...`
- 设置：`GET/POST /api/设置`

## 可复现夹具（四套，自检通过才退出 0）

1. `切流后打红`（red_after_switch）：绿放行 → 连续打红 → 计数 → 阈值超标。
2. `红灯仍放行`（red_while_released）：放行前探针已红且超标，放行不抹平红态，
   整笔仍 `已放行`，缺口全站可核。与夹具 1 **分开复现**。
3. `并发翻转`（concurrent_flip）：栅栏让 N 个打红请求与生产切流同时开打，
   原子计数保证失败次数精确等于并发红数，结局与多次重放稳定可复现。
4. `半截无实例挂接`（half_attach）：注入跳过挂接 → 全站核 `无实例挂接` →
   幂等重放补挂为 `探针待报` → 再转绿。

每套夹具都对齐以下产物：`放行回执`、`名册产版本`、`实例健康行`、
`探针失败次数`（含阈值）、`对账缺口标`、`总览红灯已切流露口`、`审计切流记录`。

HTTP 夹具端点：

```text
POST /api/夹具/切流后打红
POST /api/夹具/红灯仍放行
POST /api/夹具/半截挂接
POST /api/夹具/并发翻转
POST /api/夹具/套件          # body 可选 {"并发轮数": 3}
```

命令行（报告默认写到 `backend/fixtures/report.json`）：

```bash
cd backend
.venv/bin/python run_fixtures.py --rounds 3          # 本地临时隔离库直跑
.venv/bin/python run_fixtures.py --scenario half_attach
.venv/bin/python run_fixtures.py --base-url http://127.0.0.1:11800 --rounds 3
```

## 本地开发与测试

后端（系统 Python 缺依赖时，先建虚拟环境）：

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest tests/ -q
SHIPGATE_DB=/tmp/shipgate-dev.db .venv/bin/uvicorn app.main:app --port 11800
```

前端：

```bash
cd frontend
npm install
npm run dev       # vite，/api 代理到 127.0.0.1:11800
npm run build
```

- 前端开发地址 http://127.0.0.1:6800（以 vite 配置为准）
- API http://127.0.0.1:11800
- 数据库环境变量 `SHIPGATE_DB`（容器内默认 `/data/shipgate.db`）

## Docker Compose

```bash
docker compose up -d --build
```

对外端口：前端 http://127.0.0.1:6800 ，API http://127.0.0.1:11800 。
